# Film camera tracker (Vinted)

Месячное наблюдение за плёночными камерами на vinted.de: какие появляются, какие продаются и как быстро.
Главная цель — найти камеры, которые продаются **быстрее 30 минут**.

Этот репозиторий **публичный**: здесь только код. Никаких данных, ID таблицы, имени приватного репозитория и ключей в коде и логах.

## Архитектура

```
Этот репозиторий (public)  — код + GitHub Actions по расписанию (минуты без лимита)
   ├─→ приватный репозиторий с данными (секрет DATA_REPO, токен DATA_TOKEN) — источник истины, JSON
   └─→ Google Таблица (секрет SHEET_ID, сервисный аккаунт GOOGLE_SA_KEY) — витрина и анализ
```

Секреты Actions: `GOOGLE_SA_KEY`, `SHEET_ID`, `DATA_TOKEN`, `DATA_REPO`; для писем — `MAIL_USER` (Gmail-отправитель), `MAIL_APP_PASSWORD` (пароль приложения Google), `MAIL_TO` (необязательно, получатели через запятую; по умолчанию `MAIL_USER`).
Сервисный аккаунт Google уже имеет доступ «Редактор» к таблице.

## Источник данных: Vinted

- Старый JSON API (`/api/v2/catalog/items`, `/api/v2/items/...`) **закрыт** (404/403). Работаем со страницами.
- Сессия: `GET https://www.vinted.de/` выдаёт куки (`access_token_web` и др.), дальше обычные GET.
- Каталог: `https://www.vinted.de/catalog?catalog[]=3076&order=newest_first&page=N`
  - категория **3076 «Filmkameras»** (3077 Sofortbildkameras — НЕ берём; но продавцы выставляют камеры из списка и в 3077 (Nikon EM), 3714 «Andere Kameras» (Canon AV-1, F-1) и 3717 «Kamera-Ersatzteile» (AE-1 Program; отсюда — только если заголовок называет камеру или комплект: Kamera, appareil, body, mit Objektiv…): страница 1 каждой из них читается в каждом тике и быстрой проверке (в тиках с полным обходом — утренний после ночи и раз в 4 часа — страницы 1–3: за 7 ночных часов новое уходит со страницы 1), берутся **только камеры из списка** без флагов — новые как новые, более старые (id ниже верха каталога) — с флагом `found`; поиск старых по моделям идёт во всех четырёх категориях)
  - 96 товаров на страницу, максимум 10 страниц (`total_entries` ограничен 960)
  - в HTML встроен JSON (кавычки экранированы `\"`): `"productItem":{"id":…,"title":…,"url":…,"price":{"amount":"119.00"},…,"user":{"id":…},…,"itemBox":{"firstLine":"<бренд>","secondLine":"<состояние>"}`
  - выдача включает продавцов из других стран ЕС (FR, IT, NL…) — берём всех
  - «newest_first» включает поднятые старые объявления → новое отличаем по id (id растут со временем)
  - старые камеры из списка (выставлены не больше 6 месяцев назад, флаг `found`) ищутся поиском (`search_text`, relevance): (1) дешёвые ≤ 20 € — по 18 брендам раз в сутки (до 4 страниц на бренд, 3 страницы и 6 проверок возраста за тик); (2) любой цены — по каждой модели словаря (до 10 страниц на модель, непрерывно). Поиск — в категориях 3076, 3077, 3714 и 3717 сразу. Первый проход ускорен, чтобы закончиться к воскресенью 18.10: 7 страниц и до 60 проверок возраста за тик (потолок 115 запросов за тик; описаний до 15, проверок найденных до 15); дальше сам переходит на 2 страницы за тик, проверки — только новых кандидатов. В тиках с полным обходом каталога поиск пропускается. Возраст при обнаружении оценивается по id (`tracker/ageest.py`: шкала id → дата по карточкам с известным «Hochgeladen», скользящая медиана + интерполяция; при < 30 опорных точек — страница товара); id < 8,3 млрд отсеиваются без запроса. Первый проход по моделям — 20 страниц за тик. Затем каждую найденную карточку один раз открывают («уточнение»: точный возраст, описание, комплект, статус; дешёвые ≤ 20 € первыми; 20 за тик, после первого прохода 40); старше полугода по точному возрасту — убирается из данных. Продажа: камера пропала из результатов своей модели (или, если дешёвая, из ежедневного поиска своего бренда) → открыть страницу; плюс плановая проверка (см. ниже). Появление в поиске по релевантности — не проверка (не откладывает плановую); в свежем поиске — проверка (см. «Расписание»). В статистику скорости не входят. Объявления новее всего, что видел каталог, поиск не берёт: это новые, их забирает каталог. Объявления, скрытые из выдачи vinted.de (видны только по ссылке), найти нельзя
  - поднятые объявления камер из списка тоже отслеживаются (флаг `bumped`, время — от поднятия: между прошлым тиком и первым появлением наверху); в корзины «Сводки» не входят, в «Быстрые продажи» входят с флагом
  - фильтры `price_from` / `price_to` работают
- Страница товара: `https://www.vinted.de/items/<id>`
  - **активный**: JSON-LD `@type: Product` с `offers.availability: "InStock"`, `"can_buy":true`; описание в JSON-LD и `"description":"…"`
  - **продан**: страница остаётся (200), JSON-LD нет, `"can_buy":false`, в боковой панели `web_ui__Cell__success` с текстом **«Verkauft»**; цена и описание сохраняются
  - **зарезервирован**: `"is_reserved":true`; **скрыт**: `"is_hidden":true`
  - **удалён**: ещё не проверено — предположительно не 200 или редирект не на `/items/<id>`; уточнить на пилоте
  - времени выставления и времени продажи Vinted **не отдаёт** → время = наши проверки
- Темп: ~45 новых камер/час по всей категории (один замер), ~9% из них — из списка.
- Страница ~3,8 МБ (без сжатия). Паузы 2–3 с между запросами, один поток.

## Что отслеживаем

**Список** — камеры из списка ниже (поиск по заголовку, при необходимости по описанию).
**Остальные** (вариант Б) — всё прочее в категории с ценой **≥ 3 €**, только первые 3 часа, низший приоритет. Кроме неинтересного — такое в данные не попадает вовсе (`models.junk_reason` по заголовку, `tick.is_junk`): аксессуары, цифровые и мыльницы по флагам; Polaroid / Instax / instant; APS, 110, 126, Instamatic, Pocket; компакты (Prima, mju, Espio, Trip, XA, Sure Shot, AF230, Contax T, Leica C2 / Mini, «zoom 115», point & shoot…); экшн-камеры и дроны (DJI, Osmo, gimbal, GoPro, Insta360); игрушки, Brownie, коробочные, одноразовые, Lomo / Holga / Diana, Chicco; кино (Super 8, cinepresa, Bolex, проекторы); вспышки, экспонометры, принтеры, чехлы Instax (если с них начинается заголовок); объективы без камеры; современные автофокусные (Nikon F50–F90 / F401–F801 / N8008, Minolta AF / Dynax, Canon EOS, Pentax MZ / Z, «autofocus»); отклонённые пользователем модели (Nikon F-301, Olympus OM30, Yashica FX-7); без слова-камеры и бренда камеры — фильтры, просмотрщики, бумага, лампы. При смене словаря уже собранное такое удаляется из данных (и лист «Остальные» переписывается). Заголовки без информации («Appareil photo», «Kamera») остаются — по тексту их не отличить.

## Расписание (время берлинское, окно 07:00–00:00)

Запуск (tick) через случайные 13–18 минут (не в ровное время, с секундами) по `Europe/Berlin` (переход на зимнее время 25.10.2026); первый тик дня — в случайное время 07:03–07:12.
Между тиками — проверка «до 20 €» (`tick --cheap`) на 1/6, 1/2 и 5/6 промежутка (то есть каждые ~2–3 мин; сразу после тика пропускается): страница 1 «новых» с ценой ≤ 20 € в 3076 + 3077 + 3714 одним запросом (запчасти 3717 не берём); новые карточки заводятся, описания читаются сразу (дешёвая камера из списка попадает в «До 20 €» и в письмо за минуты); пропавших не проверяет, верх каталога и время тика не двигает (своя отметка `last_cheap_at`; у дешёвых новых «выставлена после» = позднейшая из отметок); старые незнакомые из списка — с флагом `found`. Дешёвые (≤ 20 €) камеры списка, заведённые без описания (`found` — из проверки «до 20 €», свежего поиска), получают описание в том же тике или проверке (до 10 за запуск, сначала дешёвые), а до этого в «До 20 €» и письма не попадают: в описании прячутся инструкции («Praktica MTL50» — «Mode d'emploi…»); такое (и всё, что описание сделало мусором) удаляется из данных, а id запоминается (`junk_ids`, до 3000) — больше не заводится. +~30 запросов в час (плюс ~20 описаний дешёвых без модели). И две быстрые проверки — примерно на 1/3 и 2/3 промежутка (± 40 с) — быстрая проверка (`tick --quick`): только страница 1 каталога — новые объявления, описания новых камер из списка, страницы пропавших свежих камер из списка (быстрые продажи); без поиска, плановых проверок и пропавших «Остальных». Таблица и строка «Запусков» («Полный обход»: «быстрая») пишутся, только если «Список» изменился. Цель — новая камера в «Списке» через ≤ 5–6 минут после выставления (+~10 % запросов к Vinted).
Свежий поиск по «Модели»: каждая модель листа «Модели» раз в час (до 16 моделей за тик или быструю проверку и 5 — за проверку «до 20 €», сначала дольше всех ждавшие; у быстрой проверки на запросы 2,5 мин), `search_text` + `order=newest_first`, категория **3054 «Kameras & Zubehör» со всеми подкатегориями** (не все категории Vinted: там попадалась одежда — платье «Fantasia Zenit e colori»); страниц — 1 + активных камер модели / 35 (до 8; страница всех категорий вмещает ~40 камер модели, чуть глубже — чтобы продажи популярных моделей ловились в пределах часа); у Canon AE-1, Yashica FX-3 Super 2000, Olympus OM-10 — 1 + активных / 25 (до 10) и ещё страница 1 в каждом тике. Всего ~230 запросов в час. Камера из данных в результатах — активна, это считается проверкой (страница товара тогда — раз в 5 дней); камера, которую раньше видели в результатах её модели, а теперь нет (хотя по id она в пределах прочитанных страниц), — на проверку страницы в следующем тике. Камера из списка, которой нет в данных, с id между верхом каталога сутки назад (по истории верха или по самым старым новым карточкам за сутки) и сейчас (выставлена за последние сутки, но не в «Filmkameras») — заводится; «выставлена после» = прошлый запрос этой модели, если её id выше верха каталога в тот момент, иначе (и при первом запросе) — флаг `found`. Новее верха каталога — пропускаем (заберёт каталог).
Cron GitHub ненадёжен (на старте пилота не сработал ни разу), поэтому workflow — самоподдерживающаяся цепочка (`tracker/loop.py`):
один запуск тикает до 5,5 ч, затем сам стартует следующий (его первый промежуток отсчитывается от его старта, через минуту после последнего тика) (`gh workflow run` встроенным токеном); перед каждым тиком подтягивает свежий `main`.
Сбой или превышение времени у быстрой проверки или проверки «до 20 €» не считается сбоем запуска (GitHub не шлёт письмо об ошибке); считаются только сбои тиков. Два тика подряд со сбоем — запуск сразу передаёт эстафету следующему: тот получает новую машину GitHub и новый адрес (Vinted иногда не пускает адрес машины: «home page http 403» на каждый запрос).
Cron (каждые 2 ч) — только запасной перезапуск цепочки. Старт: Run workflow вручную. Стоп: Disable workflow (после текущего запуска) и отмена запуска (сразу). `TRACKER_ENABLED=true` нужен только запасному cron.

| Возраст | Список | Остальные |
|---|---|---|
| 0–1 ч | каждые 15 мин | каждые 15 мин |
| 1–3 ч | каждые 20 мин (по факту 15: та же страница выдачи, бесплатно) | то же |
| 3–24 ч | каждые 4 часа | — (закрываем как «не продано за 3 ч») |
| 1–30 дней | 1 раз в день (нагрузку размазать по тикам) | — |
| > 30 дней | закрыть «не продано за 30 дней» | — |

Механика:
- каждый тик: страницы 1–2 каталога; раз в 4 часа: страницы 1–10
- камера «пропала», если её нет в выдаче, а её id ≥ минимального id на просмотренных страницах (иначе она просто уехала ниже) → открыть страницу товара → статус
- ежедневные проверки списка (возраст > 24 ч): очередь, ограниченное число на тик; камеры, которым на Vinted больше 30 дней (по «Hochgeladen», запоминается при первом открытии страницы товара), — раз в 5 дней
- на запросы к Vinted у тика не больше 9 минут (остальное — в следующий тик; Таблица и данные пишутся всегда); 3 сбоя связи/429/5xx подряд = блокировка
- приоритет запросов: каталог → список → остальные. При ошибках (403/429/капча/нет товаров в выдаче) — остальные отключаются до конца дня; если сломан каталог — завершить тик с ошибкой (GitHub пришлёт письмо)
- первый запуск: всё увиденное помечается `preexisting` (время выставления неизвестно), в статистику скорости не входит
- ночь: камеры, впервые увиденные в первом утреннем тике, помечаются `night` и не входят в статистику «< 30 мин»

## Поля карточки

`id, url, title, description, condition, brand, model, model_source (title/description/brand_only/photo/manual), in_list, mech_type (механическая / полуавтомат-электронная), region, format (35mm/medium), kit (body / with_lens / extras / unklar), kit_details[], seller_id (только для склейки дублей), price_start, price_final, price_history[{at, price}], favourites (сохранения пользователей: каталог `favouriteCount`, страница товара `favourite_count`), favourites_history[{at, count}], listed_after, first_seen, last_seen_active, sold_detected_at, status (active/reserved/hidden/sold/deleted/unsold_3h/unsold_30d), time_to_sell_min, time_to_sell_max, flags[] (preexisting, night, accessory?, digital?)`

- Время — дата + время по Берлину, до минуты.
- Время продажи — диапазон: `[last_seen_active, sold_detected_at]` минус время выставления.
- Время выставления — диапазон `[listed_after = предыдущий тик, first_seen]`.
- Доставку **не** собираем.
- Корзины для анализа: **< 30 мин** (главная), 30 мин–6 ч, 6–24 ч, 1–7 дн, > 7 дн.
- «Продали за» (`days_to_sell`): для новых — от `listed_after` до обнаруженной продажи; для `found`/`bumped`/`preexisting` — от даты «Hochgeladen» (`vinted_listed_est`) до середины интервала [`last_seen_active`, `sold_detected_at`] (проверки у них редкие); в таблице днями до 30, дальше месяцами.

## Хранение

Приватный репозиторий данных: `items/active/<id>.json`, при закрытии → `items/closed/<YYYY-MM>/<id>.json`; `runs.jsonl`; ежедневно `listings.csv`, `price_history.csv`, `summary.json`, `README.md` (сводка).
Таблица: листы «Список» (каждый тик), «Остальные» (раз в сутки), «До 20 €» (каждый тик: активные строки «Списка» с текущей ценой ≤ 20 € и моделью из листа «Модели»; сразу после «Цены старт» — «Средняя цена продажи, €» модели (как в «Модели», «нет данных» без продаж; на месте столбца «Группа» — там все из «Списка», так что столбцы подсветки не сдвигаются); ссылка — в столбце I, сразу после «Сохранений»; проданные, удалённые, резерв и скрытые остаются только в «Списке»/«Продажах»), «Продажи» (каждый тик: проданные камеры из списка, компактно — 13 столбцов, строка на продажу: модель, цена при продаже, история цены «150 → 140», изменение «−10 € (−7 %)», когда выставлена, когда продана, «В продаже» — сколько была в продаже: мин / ч / дни / месяцы / годы (без даты выставления — «≥ …» от первого появления), «Перевыставлялась» — «2 раза, на рынке всего 3 месяца, первая цена 150 €» (тот же продавец и модель, прошлое объявление снято без продажи: удалено / не продано за 30 дней, и новое появилось после того, как старое последний раз видели активным; два одновременно активных — не цепочка), комплект с деталями, состояние, сохранения, начало описания (150 знаков в одну строку; полное — в данных), ссылка), «Быстрые продажи» (каждый тик: проданные камеры из списка (быстрые продажи «Остальных», например мыльниц, — только в «Сводке»), нижняя оценка времени продажи < 30 мин; «точно», если верхняя ≤ 30 мин, иначе «возможно»; без preexisting/night/аксессуаров/цифровых), «Проверка» (каждый тик: подозрительные строки «Списка» с причиной — слова-аксессуары/запчасти *перед* моделью в заголовке (после модели — это комплект); цена не признак: камеры бывают и за 5–10 €; исправление — id в «Ручной разметке»: «не камера» или верная модель), «Запуски» (по строке на тик, **новые сверху**; сразу после времени — «Новых в «До 20 €»» и «Комментарий», дальше счётчики; в «Комментарии» — какие камеры добавлены в список и какие из него проданы, с моделью, ценой и id (по id строка находится в «Списке» через Ctrl+F); в логи Actions названия не попадают; «Новых в «До 20 €»» — сколько камер вошло в этот лист с прошлого тика, их модели и цены — в «Комментарии»; «Проверок между тиками» — в строке тика: сколько быстрых и «до 20 €» прошло с прошлого тика (сами они пишут строку, только если «Список» изменился)), «Сводка» (по моделям, кроме прочего, — «Средняя цена, €» (по всем камерам модели: текущая цена, у проданных — цена продажи; без заглушек и флагов), «Средняя цена продажи (> 40 €), €» (только проданные дороже 40 €) и «Непроданные висят (в среднем)»: сколько в среднем висят в продаже непроданные камеры модели — активные и скрытые до сейчас, удалённые и не проданные за 30 дней до закрытия; от выставления (у старых — дата «Hochgeladen», если её нет — первое появление); без проданных и резерва; в листах с товарами ячейка «активен» в столбце «Статус» — светло-зелёная 3, условное форматирование; в «Списке» строки новых объявлений, впервые увиденных за последние 12 ч, — светло-голубые 3, за последние 3 ч — светло-зелёные 3 (как «активен») (по служебным столбцам «Новая (12 ч)» и «Новая (3 ч)»; found/bumped/preexisting не подсвечиваются); в «До 20 €» так же, но подсвечивается всё, что появилось в листе, включая found/bumped), «Топ-10» (каждый тик: четыре таблицы — модели, которые чаще всего продаются (продано, всего было, доля проданных, средняя цена продажи — по всем продажам и по продажам > 40 €, медиана «продали за»); самые дорогие модели по средней цене продажи > 40 € (и по всем продажам, с максимальной ценой и числом продаж); продажи дороже 100 € по моделям (сколько, средняя цена продажи, сколько были в продаже — медиана и среднее, самая высокая цена); 10 самых дорогих проданных камер (модель, цена, когда продана, сколько висела, заголовок, ссылка); без заглушек и флагов), «Аналитика» (каждый тик, без заглушек и флагов: что связано с быстрой продажей — по группам «камер / продано / % / < 30 мин / продали за (медиана) / средняя цена продажи»: цена объявления против медианы своей модели (модели от 5 камер; ≤ −30 %, −30…−10 %, ±10 %, +10…+30 %, > +30 %), час и день недели появления (только новые), состояние, комплект, сохранения за первый час (0 / 1–2 / 3–5 / 6+, новые); перевыставления — сколько камер, объявлений, проданы в итоге, сколько всего на рынке, изменение цены, по моделям; цены по месяцам выставления — топ-10 моделей по числу камер, средняя цена объявления за 6 месяцев (у старых — цена при обнаружении) и средняя цена продаж за 7 дней против 8–14 дней назад; «< 30 мин» — только новые объявления), «Модели» (редактирует пользователь; фильтр для «До 20 €»; скрипт дописывает только новые модели словаря, один раз; столбец «Средняя цена, €» сразу после столбцов пользователя пишет трекер в каждом тике — как «Средняя цена» в «Сводке», «нет данных», если камер модели в статистике нет; рядом — «Средняя цена продажи, €»: только проданные камеры модели, без заглушек, флагов и наборов, как в «Продажах»; строки сопоставляются по модели в столбце A), «Ручная разметка» (id → модель, имеет приоритет, скрипт не перезаписывает; id, которого нет в данных (модель видна только на фото, или объявление не попалось в выдаче), с моделью из списка — трекер сам открывает страницу (до 5 за тик, 3 попытки) и заводит карточку с флагом `found`).
Логи Actions — только агрегаты («новых 3, продано 1»), без заголовков и id.

## Разметка по фото

`tracker/photos.py`, бесплатно и локально, без API: в каждом обычном тике (не в быстрых и не «до 20 €»; не позже 9 мин от начала тика; до 90 с) новые карточки «Остальных» с фото размечаются по первому фото объявления (ссылка из выдачи, скачивание с паузой 2–3 с). CLIP (ViT-L-14, laion2b, на процессоре) сравнивает фото с галереей отпечатков (`photo_gallery.pt` в приватном репозитории: камеры «Списка» по модели из заголовка; виды мусора по текстовым правилам; прочие камеры; примеры пользователя «не надо») и с описаниями «камера / посторонние вещи»; OCR (RapidOCR) читает надпись на камере. «Остальные» оставляют только то, что похоже на камеры **из списка**: 5 ближайших фото моделей списка должны быть хотя бы на 0,03 ближе, чем 5 ближайших прочих (мыльницы, игрушки, кино, зеркалки не из списка — Chinon, Bronica, FM10 — и примеры пользователя). Вердикт `photo_label`: убрать или «фото нет» (объявления уже нет) — **карточка удаляется из данных** (и перенесённая в «Список» по фото, если её потом отвергли) (короткая запись остаётся в `photo_dropped.json`, до 3000 последних); «в Список» (модель по надписи или по виду) — **только подсказка**, в «Список» по фото ничего не переносится (надпись путает адаптеры, журналы, задники); оставить; фото нет. Ручная разметка и «Список» не трогаются. Лист «По фото: оставить» (подсказки «в Список» сверху; фото формулой IMAGE, название, вердикт, на что похоже, надпись; до 2000 строк, новые сверху). Листа удалённого нет (убран, чтобы не грузить таблицу): записи — только в данных, `photo_dropped.json`. Вердикты, посчитанные вне трекера (архив, перепроверки), лежат файлом `photo_labels_backfill.json` в данных — тик переносит их на карточки один раз за версию файла, поверх прежних. Без библиотек или галереи шаг выключен; сбой не роняет тик; в логах только числа. Библиотеки ставит workflow (torch для CPU, open_clip, rapidocr), модель кэшируется. Точность (каждый пример без самого себя, 73 примера пользователя): камеры моделей списка остаются в 92 % случаев, примеры «не надо» отсекаются в 78 %.

## Точное название камеры («Остальные»)

У каждой карточки «Остальных» — поле `camera_name` («Minolta X300S», «Zeiss Ikon Contessa LK», «Kodak Retina IA») и откуда оно (`camera_name_source`: заголовок → описание (первые 300 знаков) → надпись на фото, прочитанная OCR): бренд из широкого списка производителей (не только бренды списка) и сразу за ним модель — токены с цифрой, известные названия (Contaflex, Retina, Comet, Electro…), коды заглавными (LB, SFX, GSN), римские цифры (IIa), одиночная буква после номера («35 S»), первое слово с заглавной сразу после бренда («Agfa Selecta»); стоп — «с / mit / + …», объективы (Rokkor, Nikkor…), диапазоны «28-80», годы, слова-состояния, серийные номера с фото. Считается в каждом обычном тике (`tick.name_step`), без запросов. В листах «Остальные» и «По фото: оставить» название стоит в столбце «Модель» / «Камера» (источник — «название: …»). Модель из списка, прочитанная на фото оставленной карточки (не «убрать», без флагов), переносит карточку в «Список» (`model_source: photo`; закрытая «не продано за 3 ч» переоткрывается и отслеживается как камера списка; пересчёт словаря такую модель не трогает). Каждая карточка «Остальных» с вердиктом по фото — ровно на одном листе: «Предложение» (точное название вне списка и не «брат»: одинаковые модели подряд, самые частые сверху, «таких объявлений»; для выбора новых моделей в список), «Братья моделей списка», «По фото: без названия», «По фото: оставить» (ещё не разобранные). На листах «Предложение» и «Братья моделей списка» — столбец «Тип» (`tracker/kinds.py`, по марке и серии модели, из истории камер): механика / полуавтомат / электроника / автофокус / мыльница / кино, «?» — если не известно (переименованные марки магазинов: Revue, Porst…). Мыльница, автофокус или кино по точному названию — карточка «Остальных» удаляется из данных, как мусорный заголовок (`tick.unwanted_kind`; запись в `photo_dropped.json` с причиной «по названию: …»), кроме набора, где есть камера другого типа или неизвестного. Лист «Братья моделей списка» (каждый тик): карточки, чьё название — та же марка и та же серия букв, что у модели списка (Minolta X-300 рядом с X-700, Nikon F-301 рядом с F/F2/F3, Olympus OM30 рядом с OM-1…) — для решения пользователя, добавлять ли их в список. Без названия после первого фото: трекер открывает страницу объявления (1 запрос, пауза 2–3 с; там все фото — в выдаче только первое) и читает надпись на 2-м и 3-м фото (`photo_more_ocr`; до 60 с за обычный тик, каждая карточка один раз — `name_tried`); заодно подтягивает описание. Название оттуда — источник «надпись на 2-3 фото», модель из списка так же переносит в «Список». Если и после трёх фото названия нет — лист «По фото: без названия» (три фото формулой IMAGE, на что похоже, заголовок, цена, ссылка): пользователь вписывает название в «Ручную разметку» (id → название; модель списка переводит в «Список», другое — остаётся названием в «Остальных»).

Разбор листов пользователем: зелёный — добавить в список, красный — не нужно, плюс комментарии. Workflow «review export» (вручную) выгружает значения, цвета, заметки и комментарии (Drive API) листов в `review/export.json` в данных. Решения по карточкам — в `photo_labels_backfill.json`: `model` (модель списка → карточка в «Список», `model_source: manual`), `camera_name` (название), красные — `drop` (удаляются из данных); зелёные модели — в словарь. `tick.REVIEW_HOLD = True` — пока пользователь размечает, листы ревью не переписываются; после применения цвета снимаются один раз.

Лист «Наборы» (каждый тик): объявления с несколькими камерами или лоты (`bundle` — названия камер из заголовка и начала описания: две и больше марки-модели, или lot / set / Konvolut / «2x» с одной) — цена не одной камеры; в «Флагах» — «набор». Наборы считаются только в «Сводке»: в «Продажи», «Быстрые продажи», «Топ-10», «Аналитику», перевыставления и продажи модели в письмах не входят; в «До 20 €» и письма попадают.

## Уведомления (письма Gmail)

`tracker/notify.py`: письмо — только когда в лист «До 20 €» попадает новая камера (тот же фильтр, что у листа: активные камеры «Списка» ≤ 20 € с моделью из «Модели»; новые, найденные поиском, поднятые и подешевевшие). После каждого тика и быстрой проверки — не больше одного письма со всеми вошедшими камерами (фото — первое фото объявления: из выдачи, у старых — со страницы товара, поле карточки `photo`; модель, цена, откуда: новое / найдено поиском / поднято, продажи этой модели в базе — средняя цена и разброс от меньшей к большей, число продаж, среднее время продажи, заголовок-ссылка, начало описания — 300 знаков; камеры в письме — от дешёвой к дорогой; у каждой отдельные абзацы: модель и цена, продажи модели, объявление, описание; камеры разделены чертой); каждая камера — один раз. Камеры брендов Praktica, Pentax и Zeiss Ikon и модели Canon T50, T60, T70 в письма не попадают (в листе «До 20 €» остаются). Письмо — только если цена камеры хотя бы на 50 € ниже средней цены продаж её модели в базе (как в «Продажи модели» письма: без заглушек, флагов и наборов) или продаж модели ещё нет (`notify.worth_a_letter`, `MAIL_MARGIN`); не прошедшая камера не помечается разосланной — если средняя цена изменится и она пройдёт, письмо придёт тогда. Тема письма начинается с «⚡». Первое письмо — «уведомления включены, сейчас в листе N камер»; лист в этот момент — точка отсчёта (не рассылается). Без секретов почты ничего не отправляется; сбой отправки не роняет тик; в логах — только «notify: mailed N».

## Классификация

Порядок: заголовок → описание → бренд + тип по ключевым словам (DE/FR/IT/NL/EN) → бренд Vinted → фото (вручную, раз в неделю, только быстрые продажи без модели) → ручная разметка.
- длинные названия раньше коротких (AE-1 Program раньше AE-1); год после модели — не номер другой модели («Leica IIIf 1954», «Nikon F 1975»; а «F 801» — другая); видоискатель после модели вместе с объективами через «+» — комплект камеры («Nikon F2 viseur DP1 + Nikon 100mm»); регистр, дефисы, пробелы нормализуются; между брендом и моделью может стоять одно слово о камере («Canon Kamera F-1», «Nikon analoge FM2»)
- кириллица → латиница: Зенит = Zenit/Zenith, ФЭД = FED, Зоркий = Zorki/Zorkij, Киев = Kiev/Kiew
- ложные совпадения: «Nikon F» ≠ F55/F60/F-301/F80…; Spotmatic ≠ Spotmatic II / 500 / 1000 / SP1000 / SP500; Pentax KX ≠ цифровая K-x; Pentax KM ≠ цифровая K-m; Canon EF (камера) ≠ объективы «EF 50mm»; «Canon 7» ≠ цифровая 7D / EOS 7; «Canon P» ≠ Prima / PowerShot; OM-1 ≠ OM-10, OM-4 ≠ OM-40; Pentax 67 ≠ 67II; Hasselblad 500C ≠ 500C/M; Yashica Mat-124 ≠ Mat-124G; Spotmatic ≠ Spotmatic F; Minolta SR-7 ≠ SR-T; Olympus Pen F ≠ цифровая PEN-F 2016 г. и M-1 ≠ цифровые E-M1 / OM-D: если в заголовке или описании признаки цифровой (M.Zuiko, Micro Four Thirds, сенсор, мегапиксели, mirrorless, зарядка/аккумулятор, LCD, видео…) — `digital?`; так же OM-1 (и OM-1 MD) ≠ цифровая OM System OM-1 2022 г. / Mark II, но для OM-1 и M-1 — только признаки Micro Four Thirds (M.Zuiko, MFT, мегапиксели, mirrorless, EVF, «OM System OM-1», OM-D, E-M1, Mark II): у плёночной OM-1 в описаниях бывают «hybride», «video», «digital» («pas hybride»)
- аксессуары (winder, Zubehör, accessoires, Tasche/Objektiv only…) без признаков камеры → флаг `accessory?`; печатная продукция (каталоги, проспекты, брошюры, книги — ouvrages, publications, Bücher, livres, libri, boeken, руководства/guide; плакаты и реклама, в рамке или без — affiche, publicité, Werbeplakat, pubblicità, encadrée, gerahmt…) — тоже `accessory?`; запчасти (ricambio, Ersatzteil, spare part, parts (кроме «parts or repair»), dial, calotta, top cover, фокусировочный экран — écran de visée / Mattscheibe / focusing screen, рулетка перемотки — manivelle / rembobinage / Rückspul…; светоуплотнители — light seals / guarnizioni / Lichtdichtungen, но только *перед* моделью: после неё это реклама камеры; брелоки, украшения, магниты, наклейки и значки в виде камеры — ciondolo, pendentif, collana, magnet, sticker, pin badge, Anstecknadel, spilla, memorabilia…; бленды — paraluce, Gegenlichtblende, pare-soleil, lens hood; чехлы — custodia, astuccio, housse, hoes, funda (как Tasche/etui); одежда и обувь — abito, vestito, Kleid, robe, dress, giacca, Schuhe…) — `accessory?`, но «на запчасти» (per/für/for … ricambi) — это камера; цифровые (Dimage, digital, Megapixel…, миниатюры Minox «Leica M3») → `digital?`
- объектив *после* модели — комплект («Canon AE1 Program | canon f1.8 … lens»; объективы отдельно называют байонет, а не камеру); «lot / set / kit / bundle / lotto / konvolut» с моделью — камера с набором; аксессуар перед моделью, но «+ / avec / mit … appareil photo / Kamera» (без «для / pour / für») — тоже камера («Objectif Sigma 28mm + appareil photo argentique Konica Autoreflex TC»)
- если заголовок помечен `accessory?`/`digital?`, модель в описании не ищется
- **база маркеров «не камера»** — `tracker/markers.py`: слова, из-за которых в «Список» попадали не камеры, на 24 языках ЕС, по видам — инструкция, журнал / книга / каталог, коробка, «камера не продаётся / пустая коробка», уровень, макрокольца / удлинительные трубки («Canon EF extension tube» — байонет EF, не камера; после объектива комплекта — камера с набором), запчасти корпуса (пластины, задняя / батарейная крышка: «Piastra inferiore Olympus OM10»; не после слова «камера» и не в наборе), «для камеры»; `models.py` нормализует их и добавляет к правилам ниже (где какое слово действует — там же). Там же слова «с» других языков (med, com, cu, με…), которые оставляют объявление камерой; однобуквенные и совпадающие с моделями и байонетами (z, s, y, ar — Konica AR, ze — Mamiya ZE-X) не берутся. Новое слово — в `markers.py`, затем проверка на всей базе
- коробка *перед* моделью — продаётся коробка («Scatola Nikon FE»: scatola / confezione / boîte / Schachtel / Verpackung / Karton / doos / caja / box) → `accessory?`; после модели — камера с родной коробкой («Leica R3 – Scatola originale»); описание, которое начинается с коробки («Confezione originale, certificato… Leica M4») или говорит «только коробка» («solo scatola vuota», «nur Verpackung», «boîte vide», «empty box», «lege doos»), — тоже `accessory?`
- «Revue Canon AL-1» (revue + другая марка в начале заголовка) и «une revue appareil…» в описании — французский журнал, не камера марки Revue → `accessory?`; «… per fotocamera / für Kamera / pour appareil / for camera» без модели и без слова-камеры перед ним — вещь для камеры (уровень — livella / Wasserwaage / niveau à bulle, ремень, лампа) → `accessory?`; описание говорит, что камера на фото не продаётся («fotocamera solo a scopo dimostrativo», «Kamera nicht im Lieferumfang», «appareil non inclus», «camera not included») → `accessory?`; модель, прочитанная по фото, уступает тексту: если пересчёт словаря находит такой признак, карточка уходит из «Списка» (и из данных)
- инструкции (Anleitung, notice, manual, libretto, manuel — если заголовок с него начинается или дальше «d'utilisation…»; «appareil … manuel» — механическая камера…) без признаков тушки/комплекта и без «с/mit/+» → `accessory?`; объективы: zoom, Vivitar, Tamron, Sigma, Tokina, Samyang, Makinon, Exaktar, Kiron, Revuenon… и «для/per/für» перед моделью → `accessory?` (слово-камера сразу после «für» — то, для чего вещь: «Exaktar 200mm 1:3,5 für Canon Cameras A-1» — объектив; марка объектива после «с / mit / +» — комплект камеры: «Spotmatic SP mit Takumar + Revuenon»); заголовок без модели и без слов-камер с производителем объективов, zoom или диапазоном «70-210mm» (объектив или мыльница) — модель из описания не берётся; модели в описании после «passt / compatible / adatto…» (в том же предложении) — совместимость, не сам товар; в заголовке «passend / passt / compatible…» сразу после модели («Canon FD 50mm 1:1.8 T50 passend») — тоже совместимость → `accessory?`; если заголовок называет бренд, модель из описания берётся только этого бренда («Olympus OM2000» с «как Canon T60» в описании — не Canon); производитель объективов между брендом и моделью не мешает («Canon Vivitar AT-1»)
- описание, которое *начинается* со слова-запчасти или инструкции (coperchio, oeilleton, manuale…), → `accessory?` всегда; со слова-аксессуара (brochure, Objektiv, Tasche…) — если не называет камеру; описание новых камер из списка загружается сразу, а также у любого нового объявления до 20 € без модели (дешёвые подписывают небрежно — «Kamera alt»; модель из описания переводит его в «Список»)
- признаки мыльницы (встроенная вспышка: flash intégré, eingebauter Blitz…; point & shoot; «Kompaktkamera / compact camera / appareil compact / fotocamera compatta» — тип камеры, не прилагательное) в заголовке или описании → `compact?` (ни у одной камеры списка нет встроенной вспышки)
- объявления с `accessory?`/`digital?`/`compact?` не входят в «Список» (группа «Остальные»), даже если в заголовке есть модель; ручная разметка снимает флаг
- цена-заглушка — 1 € (или до 5 €, если в описании «открыт к предложениям»: offen für Angebote, Preisvorschlag, VB, ouvert aux offres, faites une offre, accetto/aperto a offerte, trattabile, open to offers, make an offer, bieden…): камера остаётся в «Списке» с пометкой `price?` в «Флагах», но не входит в «Сводку», «Быстрые продажи», «Продажи», «До 20 €» и письма; считается по текущей цене (поставят настоящую — вернётся)
- **Praktica Super TL1000 — НЕ в списке**

## Объективы (отдельный сборщик)

Список — первый лист таблицы объективов («Лист1», пользователя; секрет `LENS_SHEET_ID`, сервисный аккаунт — «Редактор»), в коде — `tracker/lenses.py`: около 55 моделей (без Sigma Art и TTArtisan) и вся серия Гелиос по списку пользователя (44, 44-2/-3/-7, 44М, 44М-4…7 и МС, 44К-4, 40, 40-2, 81-Автомат / 81М / 81Н / МС 81Н, 103, 33, 65, 79, 89, 123Н; Arsat, Menopta); SMC Takumar и Orestor — все фокусные отдельными моделями. Модель — слово семейства + фокусное + светосила из заголовка («1:1.4/50», «2/58», «f/1.4»; без фокусного — только где светосила его называет: «Super takumar 1.4»), Гелиос — по номеру («Гелиос-44М-4», «MC Helios 44M-6»). Кроме списка — **все объективы Canon FD** (FD / nFD в заголовке) любой марки, модель составляется сама: «Vivitar 28mm f/2.8 (Canon FD)», «Canon FD 50mm f/1.8», зумы «Tokina 70-210mm f/4-5.6 (Canon FD)»; свои поиски (canon fd, vivitar fd…). Байонет — из заголовка, если он там назван (M42, FD, AI, PK, OM, MD, AR, C/Y, QBM, Leica M / R…), иначе модели. Диапазон зума («16-28mm») — не фокусное. Не берём: камеру с объективом (камера раньше объектива или «с / + / avec» между ними — это объявление камеры), крышки, бленды, адаптеры, фильтры, чехлы, коробки и инструкции перед названием объектива, телеконвертеры; «на запчасти / defekt» — флаг `parts?`, несколько объективов в объявлении («lot», «3 obiettivi») — `set?`; оба в цены не входят. Слово списка без фокусного («Obiettivo helios», «Tokina Objektive») — карточка `unclear`: страница объявления читается один раз, модель ищется в описании; не нашлась — лист «Не разобрано» (всё, что трекер не смог решить сам, со столбцом «Почему»: нет фокусного — модель не понять; Гелиос — вариант не из списка или без номера («Helios 44-4M», «Helios lens…»); несколько объективов в объявлении (`set?`) — чья цена, не понять; фото, заголовок, цена, начало описания, ссылка; обновление раз в неделю; размеченное в «Ручной разметке» уходит из листа; последний столбец «Комментарий» — пользователя: перед перезаписью листа читается и сохраняется по id в карточке (`comment`); высота всех строк — как у строки 2 (первой под заголовком): её задаёт пользователь под фото в столбце A). Лист «Ручная разметка» (id или ссылка → модель) — модель пользователя главнее правил. Смена правил (`lenses.VERSION`) — проверка заново классифицирует все карточки (выпавшие удаляются) и ещё раз проходит все поиски: новые правила берут то, что раньше пропускалось; новые поиски списка тоже проходят первым сбором.
Категория Vinted 3061 «Objektive» (~960 новых объявлений всех объективов в сутки). `tracker/lens_tick.py` — одна проверка: новые объявления — страницы каталога от верха прошлой проверки (до 6); страницы объявлений — каждого нового один раз (описание, «Hochgeladen», фото, статус), дальше по возрасту: до 3 дней — каждые 90 мин, до 2 недель — раз в сутки, старше — раз в неделю (продажа старого объявления видна с точностью до недели) (до 220 за проверку, новые первыми); пропало — «Verkauft» → продан, иначе удалён. Первый сбор (`backfill`): все поиски списка по релевантности, страница за страницей, пока на странице есть объективы списка (до 10 страниц); найденное — `preexisting`, начало продажи — дата «Hochgeladen»; первый сбор кончается, когда прочитаны и страницы всех найденных (до тех пор проверки идут подряд). На старте (26.10.2026) поиски прошли за одну проверку: 377 страниц, 615 объективов списка, отсеяно 36 комплектов с камерой и 3 аксессуара. 25 мин запросов на проверку, паузы 2–3 с.
`tracker/lens_loop.py` + workflow `lenses.yml` — своя цепочка запусков на своей машине GitHub (как у камер: ≤ 5,5 ч, затем сам стартует следующий; перед проверкой — свежий `main`): 10 проверок в день в окне 07:00–00:00, примерно каждые 102 мин (± 5); пока идёт первый сбор (код выхода 10) — проверка за проверкой. Два сбоя подряд — эстафета новой машине. Данные — `lenses/` в приватном репозитории (та же раскладка, что у камер).
Листы таблицы объективов: «Объективы» (все: модель, байонет, заголовок, статус, цены, сохранения, выставлен на Vinted, впервые увиден, последний раз активен, продажа обнаружена, сколько в продаже, состояние, флаги, id, ссылка), «Продажи» (новые сверху), «Сводка» (по каждой модели списка: всего, в продаже, продано, удалено, средняя / медиана / мин / макс цены объявлений, средняя / мин / макс цены продажи, «продали за» — медиана, непроданные висят — среднее, ссылка на самое дешёвое сейчас), «Модели» (модели и поиски), «Не разобрано», «Ручная разметка», «Для Canon TX / AV-1 / FTb QL» (только активные объявления объективов Canon FD и FL — без статистики, она в «Сводке»; столбец «Подходит к камерам»: FD — на всех трёх, FL — с замером на рабочей диафрагме; по модели от дешёвых), «Запуски» (строка на проверку, новые сверху).
