# Film camera tracker (Vinted)

Месячное наблюдение за плёночными камерами на vinted.de: какие появляются, какие продаются и как быстро.
Главная цель — найти камеры, которые продаются **быстрее 30 минут**.

Этот репозиторий **публичный**: здесь только код. Никаких данных, ID таблицы, имени приватного репозитория и ключей в коде и логах.

## Архитектура

```
Этот репозиторий (public)  — код + GitHub Actions по расписанию (минуты без лимита)
   ├─→ приватный репозиторий с данными (секрет DATA_REPO, токен DATA_TOKEN) — источник истины, JSON
   └─→ Google Таблица (секрет SHEET_ID, сервисный аккаунт GOOGLE_SA_KEY) — витрина и анализ
```

Секреты Actions: `GOOGLE_SA_KEY`, `SHEET_ID`, `DATA_TOKEN`, `DATA_REPO`; для писем — `MAIL_USER` (Gmail-отправитель), `MAIL_APP_PASSWORD` (пароль приложения Google), `MAIL_TO` (необязательно, получатели через запятую; по умолчанию `MAIL_USER`).
Сервисный аккаунт Google уже имеет доступ «Редактор» к таблице.

## Источник данных: Vinted

- Старый JSON API (`/api/v2/catalog/items`, `/api/v2/items/...`) **закрыт** (404/403). Работаем со страницами.
- Сессия: `GET https://www.vinted.de/` выдаёт куки (`access_token_web` и др.), дальше обычные GET.
- Каталог: `https://www.vinted.de/catalog?catalog[]=3076&order=newest_first&page=N`
  - категория **3076 «Filmkameras»** (3077 Sofortbildkameras — НЕ берём; но продавцы выставляют камеры из списка и в 3077 (Nikon EM), 3714 «Andere Kameras» (Canon AV-1, F-1) и 3717 «Kamera-Ersatzteile» (AE-1 Program; отсюда — только если заголовок называет камеру или комплект: Kamera, appareil, body, mit Objektiv…): страница 1 каждой из них читается в каждом тике и быстрой проверке (в тиках с полным обходом — утренний после ночи и раз в 4 часа — страницы 1–3: за 7 ночных часов новое уходит со страницы 1), берутся **только камеры из списка** без флагов — новые как новые, более старые (id ниже верха каталога) — с флагом `found`; поиск старых по моделям идёт во всех четырёх категориях)
  - 96 товаров на страницу, максимум 10 страниц (`total_entries` ограничен 960)
  - в HTML встроен JSON (кавычки экранированы `\"`): `"productItem":{"id":…,"title":…,"url":…,"price":{"amount":"119.00"},…,"user":{"id":…},…,"itemBox":{"firstLine":"<бренд>","secondLine":"<состояние>"}`
  - выдача включает продавцов из других стран ЕС (FR, IT, NL…) — берём всех
  - «newest_first» включает поднятые старые объявления → новое отличаем по id (id растут со временем)
  - старые камеры из списка (выставлены не больше 6 месяцев назад, флаг `found`) ищутся поиском (`search_text`, relevance): (1) дешёвые ≤ 20 € — по 18 брендам раз в сутки (до 4 страниц на бренд, 3 страницы и 6 проверок возраста за тик); (2) любой цены — по каждой модели словаря (до 10 страниц на модель, непрерывно). Поиск — в категориях 3076, 3077, 3714 и 3717 сразу. Первый проход ускорен, чтобы закончиться к воскресенью 18.10: 7 страниц и до 60 проверок возраста за тик (потолок 115 запросов за тик; описаний до 15, проверок найденных до 15); дальше сам переходит на 2 страницы за тик, проверки — только новых кандидатов. В тиках с полным обходом каталога поиск пропускается. Возраст при обнаружении оценивается по id (`tracker/ageest.py`: шкала id → дата по карточкам с известным «Hochgeladen», скользящая медиана + интерполяция; при < 30 опорных точек — страница товара); id < 8,3 млрд отсеиваются без запроса. Первый проход по моделям — 20 страниц за тик. Затем каждую найденную карточку один раз открывают («уточнение»: точный возраст, описание, комплект, статус; дешёвые ≤ 20 € первыми; 20 за тик, после первого прохода 40); старше полугода по точному возрасту — убирается из данных. Продажа: камера пропала из результатов своей модели (или, если дешёвая, из ежедневного поиска своего бренда) → открыть страницу; плюс плановая проверка (см. ниже). Появление в поиске по релевантности — не проверка (не откладывает плановую); в свежем поиске — проверка (см. «Расписание»). В статистику скорости не входят. Объявления новее всего, что видел каталог, поиск не берёт: это новые, их забирает каталог. Объявления, скрытые из выдачи vinted.de (видны только по ссылке), найти нельзя
  - поднятые объявления камер из списка тоже отслеживаются (флаг `bumped`, время — от поднятия: между прошлым тиком и первым появлением наверху); в корзины «Сводки» не входят, в «Быстрые продажи» входят с флагом
  - фильтры `price_from` / `price_to` работают
- Страница товара: `https://www.vinted.de/items/<id>`
  - **активный**: JSON-LD `@type: Product` с `offers.availability: "InStock"`, `"can_buy":true`; описание в JSON-LD и `"description":"…"`
  - **продан**: страница остаётся (200), JSON-LD нет, `"can_buy":false`, в боковой панели `web_ui__Cell__success` с текстом **«Verkauft»**; цена и описание сохраняются
  - **зарезервирован**: `"is_reserved":true`; **скрыт**: `"is_hidden":true`
  - **удалён**: ещё не проверено — предположительно не 200 или редирект не на `/items/<id>`; уточнить на пилоте
  - времени выставления и времени продажи Vinted **не отдаёт** → время = наши проверки
- Темп: ~45 новых камер/час по всей категории (один замер), ~9% из них — из списка.
- Страница ~3,8 МБ (без сжатия). Паузы 2–3 с между запросами, один поток.

## Что отслеживаем

**Список** — камеры из списка ниже (поиск по заголовку, при необходимости по описанию).
**Остальные** (вариант Б) — всё прочее в категории с ценой **≥ 3 €**, только первые 3 часа, низший приоритет.

## Расписание (время берлинское, окно 07:00–00:00)

Запуск (tick) через случайные 13–18 минут (не в ровное время, с секундами) по `Europe/Berlin` (переход на зимнее время 25.10.2026); первый тик дня — в случайное время 07:03–07:12.
Между тиками — проверка «до 20 €» (`tick --cheap`) на 1/6, 1/2 и 5/6 промежутка (то есть каждые ~2–3 мин; сразу после тика пропускается): страница 1 «новых» с ценой ≤ 20 € в 3076 + 3077 + 3714 одним запросом (запчасти 3717 не берём); новые карточки заводятся, описания читаются сразу (дешёвая камера из списка попадает в «До 20 €» и в письмо за минуты); пропавших не проверяет, верх каталога и время тика не двигает (своя отметка `last_cheap_at`; у дешёвых новых «выставлена после» = позднейшая из отметок); старые незнакомые из списка — с флагом `found`. +~30 запросов в час (плюс ~20 описаний дешёвых без модели). И две быстрые проверки — примерно на 1/3 и 2/3 промежутка (± 40 с) — быстрая проверка (`tick --quick`): только страница 1 каталога — новые объявления, описания новых камер из списка, страницы пропавших свежих камер из списка (быстрые продажи); без поиска, плановых проверок и пропавших «Остальных». Таблица и строка «Запусков» («Полный обход»: «быстрая») пишутся, только если «Список» изменился. Цель — новая камера в «Списке» через ≤ 5–6 минут после выставления (+~10 % запросов к Vinted).
Свежий поиск по «Модели»: каждая модель листа «Модели» раз в час (до 16 моделей за тик или быструю проверку и 5 — за проверку «до 20 €», сначала дольше всех ждавшие; у быстрой проверки на запросы 2,5 мин), `search_text` + `order=newest_first`, категория **3054 «Kameras & Zubehör» со всеми подкатегориями** (не все категории Vinted: там попадалась одежда — платье «Fantasia Zenit e colori»); страниц — 1 + активных камер модели / 40 (до 4; страница всех категорий вмещает ~40 камер модели); у Canon AE-1, Yashica FX-3 Super 2000, Olympus OM-10 — 1 + активных / 30 (до 6) и ещё страница 1 в каждом тике. Всего ~215 запросов в час. Камера из данных в результатах — активна, это считается проверкой (страница товара тогда — раз в 5 дней); камера, которую раньше видели в результатах её модели, а теперь нет (хотя по id она в пределах прочитанных страниц), — на проверку страницы в следующем тике. Камера из списка, которой нет в данных, с id между верхом каталога сутки назад (по истории верха или по самым старым новым карточкам за сутки) и сейчас (выставлена за последние сутки, но не в «Filmkameras») — заводится; «выставлена после» = прошлый запрос этой модели, если её id выше верха каталога в тот момент, иначе (и при первом запросе) — флаг `found`. Новее верха каталога — пропускаем (заберёт каталог).
Cron GitHub ненадёжен (на старте пилота не сработал ни разу), поэтому workflow — самоподдерживающаяся цепочка (`tracker/loop.py`):
один запуск тикает до 5,5 ч, затем сам стартует следующий (его первый промежуток отсчитывается от его старта, через минуту после последнего тика) (`gh workflow run` встроенным токеном); перед каждым тиком подтягивает свежий `main`.
Сбой или превышение времени у быстрой проверки или проверки «до 20 €» не считается сбоем запуска (GitHub не шлёт письмо об ошибке); считаются только сбои тиков.
Cron (каждые 2 ч) — только запасной перезапуск цепочки. Старт: Run workflow вручную. Стоп: Disable workflow (после текущего запуска) и отмена запуска (сразу). `TRACKER_ENABLED=true` нужен только запасному cron.

| Возраст | Список | Остальные |
|---|---|---|
| 0–1 ч | каждые 15 мин | каждые 15 мин |
| 1–3 ч | каждые 20 мин (по факту 15: та же страница выдачи, бесплатно) | то же |
| 3–24 ч | каждые 4 часа | — (закрываем как «не продано за 3 ч») |
| 1–30 дней | 1 раз в день (нагрузку размазать по тикам) | — |
| > 30 дней | закрыть «не продано за 30 дней» | — |

Механика:
- каждый тик: страницы 1–2 каталога; раз в 4 часа: страницы 1–10
- камера «пропала», если её нет в выдаче, а её id ≥ минимального id на просмотренных страницах (иначе она просто уехала ниже) → открыть страницу товара → статус
- ежедневные проверки списка (возраст > 24 ч): очередь, ограниченное число на тик; камеры, которым на Vinted больше 30 дней (по «Hochgeladen», запоминается при первом открытии страницы товара), — раз в 5 дней
- на запросы к Vinted у тика не больше 9 минут (остальное — в следующий тик; Таблица и данные пишутся всегда); 3 сбоя связи/429/5xx подряд = блокировка
- приоритет запросов: каталог → список → остальные. При ошибках (403/429/капча/нет товаров в выдаче) — остальные отключаются до конца дня; если сломан каталог — завершить тик с ошибкой (GitHub пришлёт письмо)
- первый запуск: всё увиденное помечается `preexisting` (время выставления неизвестно), в статистику скорости не входит
- ночь: камеры, впервые увиденные в первом утреннем тике, помечаются `night` и не входят в статистику «< 30 мин»

## Поля карточки

`id, url, title, description, condition, brand, model, model_source (title/description/brand_only/photo/manual), in_list, mech_type (механическая / полуавтомат-электронная), region, format (35mm/medium), kit (body / with_lens / extras / unklar), kit_details[], seller_id (только для склейки дублей), price_start, price_final, price_history[{at, price}], favourites (сохранения пользователей: каталог `favouriteCount`, страница товара `favourite_count`), favourites_history[{at, count}], listed_after, first_seen, last_seen_active, sold_detected_at, status (active/reserved/hidden/sold/deleted/unsold_3h/unsold_30d), time_to_sell_min, time_to_sell_max, flags[] (preexisting, night, accessory?, digital?)`

- Время — дата + время по Берлину, до минуты.
- Время продажи — диапазон: `[last_seen_active, sold_detected_at]` минус время выставления.
- Время выставления — диапазон `[listed_after = предыдущий тик, first_seen]`.
- Доставку **не** собираем.
- Корзины для анализа: **< 30 мин** (главная), 30 мин–6 ч, 6–24 ч, 1–7 дн, > 7 дн.
- «Продали за» (`days_to_sell`): для новых — от `listed_after` до обнаруженной продажи; для `found`/`bumped`/`preexisting` — от даты «Hochgeladen» (`vinted_listed_est`) до середины интервала [`last_seen_active`, `sold_detected_at`] (проверки у них редкие); в таблице днями до 30, дальше месяцами.

## Хранение

Приватный репозиторий данных: `items/active/<id>.json`, при закрытии → `items/closed/<YYYY-MM>/<id>.json`; `runs.jsonl`; ежедневно `listings.csv`, `price_history.csv`, `summary.json`, `README.md` (сводка).
Таблица: листы «Список» (каждый тик), «Остальные» (раз в сутки), «До 20 €» (каждый тик: активные строки «Списка» с текущей ценой ≤ 20 € и моделью из листа «Модели»; проданные, удалённые, резерв и скрытые остаются только в «Списке»/«Продажах»), «Продажи» (каждый тик: проданные камеры из списка, компактно — 12 столбцов, строка на продажу: модель, цена при продаже, история цены «150 → 140», изменение «−10 € (−7 %)», когда выставлена, когда продана, «В продаже» — сколько была в продаже: мин / ч / дни / месяцы / годы (без даты выставления — «≥ …» от первого появления), комплект с деталями, состояние, сохранения, начало описания (150 знаков в одну строку; полное — в данных), ссылка), «Быстрые продажи» (каждый тик: проданные камеры из списка (быстрые продажи «Остальных», например мыльниц, — только в «Сводке»), нижняя оценка времени продажи < 30 мин; «точно», если верхняя ≤ 30 мин, иначе «возможно»; без preexisting/night/аксессуаров/цифровых), «Проверка» (каждый тик: подозрительные строки «Списка» с причиной — слова-аксессуары/запчасти *перед* моделью в заголовке (после модели — это комплект); цена не признак: камеры бывают и за 5–10 €; исправление — id в «Ручной разметке»: «не камера» или верная модель), «Запуски» (по строке на тик; в «Комментарии» — какие камеры добавлены в список и какие из него проданы, с моделью, ценой и id (по id строка находится в «Списке» через Ctrl+F); в логи Actions названия не попадают; «Новых в «До 20 €»» — сколько камер вошло в этот лист с прошлого тика, их модели и цены — в «Комментарии»; «Проверок между тиками» — в строке тика: сколько быстрых и «до 20 €» прошло с прошлого тика (сами они пишут строку, только если «Список» изменился)), «Сводка» (по моделям, кроме прочего, — «Средняя цена, €» (по всем камерам модели: текущая цена, у проданных — цена продажи; без заглушек и флагов), «Средняя цена продажи (> 40 €), €» (только проданные дороже 40 €) и «Непроданные висят (в среднем)»: сколько в среднем висят в продаже непроданные камеры модели — активные и скрытые до сейчас, удалённые и не проданные за 30 дней до закрытия; от выставления (у старых — дата «Hochgeladen», если её нет — первое появление); без проданных и резерва; в листах с товарами ячейка «активен» в столбце «Статус» — светло-зелёная 3, условное форматирование; в «Списке» строки новых объявлений, впервые увиденных за последние 12 ч, — светло-голубые 3, за последние 3 ч — светло-зелёные 3 (как «активен») (по служебным столбцам «Новая (12 ч)» и «Новая (3 ч)»; found/bumped/preexisting не подсвечиваются); в «До 20 €» так же, но подсвечивается всё, что появилось в листе, включая found/bumped), «Топ-10» (каждый тик: три таблицы — модели, которые чаще всего продаются (продано, всего было, доля проданных, средняя цена продажи > 40 €, медиана «продали за»); самые дорогие модели по средней цене продажи > 40 € (с максимальной ценой и числом продаж); 10 самых дорогих проданных камер (модель, цена, когда продана, сколько висела, заголовок, ссылка); без заглушек и флагов), «Модели» (редактирует пользователь; фильтр для «До 20 €»; скрипт дописывает только новые модели словаря, один раз), «Ручная разметка» (id → модель, имеет приоритет, скрипт не перезаписывает; id, которого нет в данных (модель видна только на фото, или объявление не попалось в выдаче), с моделью из списка — трекер сам открывает страницу (до 5 за тик, 3 попытки) и заводит карточку с флагом `found`).
Логи Actions — только агрегаты («новых 3, продано 1»), без заголовков и id.

## Уведомления (письма Gmail)

`tracker/notify.py`: письмо — только когда в лист «До 20 €» попадает новая камера (тот же фильтр, что у листа: активные камеры «Списка» ≤ 20 € с моделью из «Модели»; новые, найденные поиском, поднятые и подешевевшие). После каждого тика и быстрой проверки — не больше одного письма со всеми вошедшими камерами (фото — первое фото объявления: из выдачи, у старых — со страницы товара, поле карточки `photo`; модель, цена, откуда: новое / найдено поиском / поднято, заголовок-ссылка, начало описания — 300 знаков); каждая камера — один раз. Тема письма начинается с «⚡». Первое письмо — «уведомления включены, сейчас в листе N камер»; лист в этот момент — точка отсчёта (не рассылается). Без секретов почты ничего не отправляется; сбой отправки не роняет тик; в логах — только «notify: mailed N».

## Классификация

Порядок: заголовок → описание → бренд + тип по ключевым словам (DE/FR/IT/NL/EN) → бренд Vinted → фото (вручную, раз в неделю, только быстрые продажи без модели) → ручная разметка.
- длинные названия раньше коротких (AE-1 Program раньше AE-1); регистр, дефисы, пробелы нормализуются; между брендом и моделью может стоять одно слово о камере («Canon Kamera F-1», «Nikon analoge FM2»)
- кириллица → латиница: Зенит = Zenit/Zenith, ФЭД = FED, Зоркий = Zorki/Zorkij, Киев = Kiev/Kiew
- ложные совпадения: «Nikon F» ≠ F55/F60/F-301/F80…; Spotmatic ≠ Spotmatic II / 500 / 1000 / SP1000 / SP500; Pentax KX ≠ цифровая K-x; Pentax KM ≠ цифровая K-m; Canon EF (камера) ≠ объективы «EF 50mm»; «Canon 7» ≠ цифровая 7D / EOS 7; «Canon P» ≠ Prima / PowerShot; OM-1 ≠ OM-10, OM-4 ≠ OM-40; Pentax 67 ≠ 67II; Hasselblad 500C ≠ 500C/M; Yashica Mat-124 ≠ Mat-124G; Spotmatic ≠ Spotmatic F; Minolta SR-7 ≠ SR-T
- аксессуары (winder, Zubehör, accessoires, Tasche/Objektiv only…) без признаков камеры → флаг `accessory?`; печатная продукция (каталоги, проспекты, брошюры, книги, руководства/guide) — тоже `accessory?`; запчасти (ricambio, Ersatzteil, spare part, parts (кроме «parts or repair»), dial, calotta, top cover, фокусировочный экран — écran de visée / Mattscheibe / focusing screen, рулетка перемотки — manivelle / rembobinage / Rückspul…; светоуплотнители — light seals / guarnizioni / Lichtdichtungen, но только *перед* моделью: после неё это реклама камеры; брелоки, украшения, магниты, наклейки и значки в виде камеры — ciondolo, pendentif, collana, magnet, sticker, pin badge, Anstecknadel, spilla, memorabilia…; бленды — paraluce, Gegenlichtblende, pare-soleil, lens hood; одежда и обувь — abito, vestito, Kleid, robe, dress, giacca, Schuhe…) — `accessory?`, но «на запчасти» (per/für/for … ricambi) — это камера; цифровые (Dimage, digital, Megapixel…, миниатюры Minox «Leica M3») → `digital?`
- объектив *после* модели — комплект («Canon AE1 Program | canon f1.8 … lens»; объективы отдельно называют байонет, а не камеру); «lot / set / kit / bundle / lotto / konvolut» с моделью — камера с набором; аксессуар перед моделью, но «+ / avec / mit … appareil photo / Kamera» (без «для / pour / für») — тоже камера («Objectif Sigma 28mm + appareil photo argentique Konica Autoreflex TC»)
- если заголовок помечен `accessory?`/`digital?`, модель в описании не ищется
- инструкции (Anleitung, notice, manual, libretto, manuel — если заголовок с него начинается или дальше «d'utilisation…»; «appareil … manuel» — механическая камера…) без признаков тушки/комплекта и без «с/mit/+» → `accessory?`; объективы: zoom, Vivitar, Tamron, Sigma, Tokina… и «для/per/für» перед моделью → `accessory?`; заголовок без модели и без слов-камер с производителем объективов, zoom или диапазоном «70-210mm» (объектив или мыльница) — модель из описания не берётся; модели в описании после «passt / compatible / adatto…» (в том же предложении) — совместимость, не сам товар; в заголовке «passend / passt / compatible…» сразу после модели («Canon FD 50mm 1:1.8 T50 passend») — тоже совместимость → `accessory?`; если заголовок называет бренд, модель из описания берётся только этого бренда («Olympus OM2000» с «как Canon T60» в описании — не Canon)
- описание, которое *начинается* со слова-запчасти или инструкции (coperchio, oeilleton, manuale…), → `accessory?` всегда; со слова-аксессуара (brochure, Objektiv, Tasche…) — если не называет камеру; описание новых камер из списка загружается сразу, а также у любого нового объявления до 20 € без модели (дешёвые подписывают небрежно — «Kamera alt»; модель из описания переводит его в «Список»)
- признаки мыльницы (встроенная вспышка: flash intégré, eingebauter Blitz…; point & shoot; «Kompaktkamera / compact camera / appareil compact / fotocamera compatta» — тип камеры, не прилагательное) в заголовке или описании → `compact?` (ни у одной камеры списка нет встроенной вспышки)
- объявления с `accessory?`/`digital?`/`compact?` не входят в «Список» (группа «Остальные»), даже если в заголовке есть модель; ручная разметка снимает флаг
- цена-заглушка — 1 € (или до 5 €, если в описании «открыт к предложениям»: offen für Angebote, Preisvorschlag, VB, ouvert aux offres, faites une offre, accetto/aperto a offerte, trattabile, open to offers, make an offer, bieden…): камера остаётся в «Списке» с пометкой `price?` в «Флагах», но не входит в «Сводку», «Быстрые продажи», «Продажи», «До 20 €» и письма; считается по текущей цене (поставят настоящую — вернётся)
- **Praktica Super TL1000 — НЕ в списке**
